# 2026-07-26 D3 受控 Project Preview 纵切

> 状态：代码、迁移、自动测试、Preview 部署、真实 E2B E2E、桌面/移动浏览器验收和最终资源清理均已完成。
> 关联：[ADR-0006](../adr/0006-controlled-project-preview.md) · [运行时边界](../architecture/02-sandbox-runtime.md) · [Preview 部署](../setup/preview-deployment.md) · [资源台账](../setup/cloudflare-preview-resources.md)

## 1. 本阶段目标

在不暴露 Provider URL、sandbox ID、内部端口或 traffic token，也不引入第二个 Worker、
Durable Object、R2、公开部署或 Preview 历史的前提下，让用户在 Project Inspector
查看当前 E2B `/workspace` 中真实 Web 项目。

这不是通用反向代理。V1 只支持平台固定的 `vite-v1` preset、固定端口和同源 GET/HEAD
内容网关；浏览器不能提交 command、args、cwd、env、端口或 Provider 参数。

## 2. 已实现

### Runtime 与应用层

- `SandboxPreviewRuntime` 与 lifecycle/process/files/terminal capability 分离，只负责固定
  Preview 启停、探测和服务端 fetch。
- `E2BSandboxRuntime` 在 public traffic 关闭的沙箱中使用服务端 traffic token；token、
  host、sandbox ID、端口和进程引用不进入公共响应。
- Preview 使用 `/workspace/node_modules/.bin/vite`、`0.0.0.0:3000` 和平台写入
  `/tmp` 的固定 config；不执行 Project script、不加载 Project Vite config、不通过
  `npx` 下载。
- config 文件 RPC 瞬时失败时先重连重试；最终 fallback 只执行平台固定内容和固定路径
  的受控写入，不接收用户命令、文件内容、Key 或 Provider 标识。
- `ProjectPreviewService` 负责 claim、启动、探测、停止、expiry 与 idle cleanup；Hono
  只处理认证、Project 授权、输入规范化和响应映射。

### D1、并发与生命周期

- migration `0005_preview_sessions.sql` 新增每 Project 最多一行的临时 Preview 所有权；
  只保存应用 ID、Lease、私有 sandbox/process reference、`starting|running`、固定端口
  和 expiry。
- 启动只允许已有 `idle|ready` E2B Lease，且当时没有活动 AgentRun/Terminal。
  `starting` 行通过 D1 trigger 阻止新 Run。
- 进入 `running` 后，后续 AgentRun 和 Terminal 可以复用同一 `/workspace`；活动
  Preview 会阻止整沙箱手动 Stop 和所有 idle cleanup。
- 显式 Stop、进程消失、探测失败或 30 分钟 expiry 会终止固定进程并删除当前行；
  随后沿用 10 分钟 Lease idle cleanup。D1 不保存页面、日志、截图或访问历史。

### 同源内容网关与浏览器

- 公共控制 API 为 `GET preview`、`POST start` 和 `POST stop`；内容只通过绑定
  Project/PreviewSession/expiry 的短时 HMAC capability 访问。
- 内容网关只转发 GET/HEAD 和少量安全请求头，移除 Cookie、Authorization、
  Set-Cookie、Provider Location/host/control header。
- HTML 使用同源 base，常见 root-relative 资源改为签名路径；iframe sandbox/CSP 禁止
  same-origin 权限、表单、弹窗、顶层导航、WebSocket 和任意 connect。
- Vite 8 固定 `@vite/client` 路径由平台最小 style runtime 替代，只提供 CSS 初始注入，
  不启动 HMR WebSocket；Vite 服务端文件监听仍保留，手动 Reload 可看到 Agent 修改。
- Preview tab 隐藏时卸载 iframe，但不擅自停止服务端 Preview；Project Inspector 提供
  明确的 starting/running/stopped/loading/error/disabled 状态和 Reload/Stop 操作。

## 3. 远程端到端验收

私有 Cloudflare 环境使用真实 E2B Project 完成以下闭环：

1. 启动固定 Preview 并加载 V1 HTML、JavaScript 和 CSS。
2. 保持 Preview 运行，完成一次真实 Pi Run，把页面更新为 V2；Run 成功写入最终
   assistant Message 和真实 usage。
3. Reload iframe 后显示 V2，证明同一 `/workspace`、Vite 文件监听和转换缓存失效路径
   生效。
4. Preview 运行期间连接真实 Terminal，读取同一文件并获得预期输出；切回 Preview
   仍保持 V2。
5. 活动 Preview 时整沙箱 Stop 返回 `409 project_busy`；显式停止 Preview 后整沙箱
   Stop 成功。
6. 独立 `preview-expiry` Workflow 以短时 future expiry 完成 sleep 与幂等 release
   步骤。
7. 最终 D1 中 `preview_sessions=0`、`terminal_sessions=0`，Lease 为 `stopped` 且
   Provider 引用已清空。
8. `1440x900` 和 `390x844` 的干净浏览器会话均成功加载 V2，控制台 0
   error/warning；响应和 DOM 未出现 E2B host、sandbox ID、内部端口或 Key。

当前部署版本、迁移清单和 Dashboard 入口记录在
[Cloudflare Preview 资源台账](../setup/cloudflare-preview-resources.md)，不在本文复制
Secret、owner 邮箱或签名 capability。

## 5. 基础设施影响

本纵切只新增：

- 一张临时 D1 表；
- 一项 `SandboxPreviewRuntime` capability；
- 一组同源 Hono 路径；
- Preview expiry/idle cleanup 两种既有 Workflow class 的 payload。

没有新增环境变量、Secret、Cloudflare 资源、外部服务、R2、Durable Object、第二个
Worker 或长期数据。运行成本仍来自现有 Worker/D1/Workflow 和 E2B 沙箱；固定 30 分钟
上限、显式 Stop 与 idle TTL 是当前成本护栏。

## 6. 剩余边界

- 只支持固定 Vite、端口 3000 和 GET/HEAD；不支持表单、应用后端 API、WebSocket、
  HMR、SSR、任意 framework preset 或动态端口发现。
- path-based 网关处理常见 HTML 资源路径，但不承诺改写任意 JavaScript/CSS 中运行时
  生成的绝对 URL。
- Preview 不是部署或分享功能，没有域名、SEO、访问统计、截图历史或持久可用性。
- 沙箱停止后 Project 文件仍允许丢失；Preview 不改变“不使用 R2 快照”的产品边界。
- 后续只读 Changes 已按 ADR-0007 独立完成；它没有通过解析 Preview 页面或保存文件
  历史伪造，也不能把当前工作树归因到某一次 Run。

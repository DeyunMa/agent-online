## 决策说明

- 不替换技术栈，不拆 Worker，不加入缓存服务或通用状态管理框架。
- 健康 SSE 下仍低频查询可信 Run 详情；现有断线查询继续使用，不以单条流作为唯一真相。
- 文件保存采用用户主动导出，不引入 R2、Git 凭据、后台同步或版本历史；沙箱仍是平台唯一工作区副本。
- 资源限制属于执行准入和调用护栏，不建立套餐、计费或财务账本。并发检查必须具有数据库原子性。
- 修改 API 合同时同步更新全部仓库消费者和测试，不保留旧响应兼容分支。

## 阶段②第三批：性能证据和用户文件保存

- Files 为成功读取的文本提供 Download displayed file，下载当前显示内容，不再向沙箱读取。
  保存文件名沿用服务端验证后的 name；不开放二进制、超大文件、目录归档或平台备份。
  页面明确单文件下载的边界。浏览器验证下载文件名、中文 UTF-8 内容及仅一次读取通过。
- 新增 performance.measured 结构化事件，测量沙箱准备、Agent 启动、取消请求处理、
  模型上游响应头、HTTP 响应建立时间。HTTP 不代表 SSE/WebSocket/流式正文的完整生命周期；
  upstream_fetch 不代表模型回复完成；cancel 不保证本次请求返回时启动中的取消已完全收敛。
- Run 历史查询与 Usage 聚合记录执行耗时及 D1 meta 的 rows_read/rows_written；Usage
  为三个查询之和，缺少 metadata 时省略计数，不能将未知成本当成零。没有修改 SQL 语义。
- HTTP 只输出固定 route 分类、状态和耗时，查询计时只输出固定 operation 分类及数字。
  不记录 URL、路径、SQL、参数、结果行或用户内容；Reporter 异常不改变产品结果。
  性能事件仅走结构化日志，不作为 Sentry error，也不启用 Sentry Tracing/Metrics。
- 测量执行工具放在 application，observability 目录仍只承载独立诊断合同。

> 状态：代码、模板、自动测试、私有 Preview 部署、真实 E2B/Gemini E2E、桌面与移动浏览器验收和最终资源清理均已完成。

## 1. 本阶段目标

在不保存 Project 文件快照、Git 历史或 Run 前后 diff，也不暴露任意 Git 命令、
revision、pathspec、Provider sandbox ID 或内部路径的前提下，让登录用户检查当前
E2B `/workspace` repository 的真实 working tree 和 index。

Changes 是当前状态视图，不是一次 AgentRun 的产物记录。连续 Run、Terminal 和用户
操作都可能修改同一 repository，平台不做归因。

## 2. 已实现

### Runtime 与应用层

- 新增窄接口 `SandboxChangesRuntime`，没有继续膨胀 lifecycle/process/files 合同。
- E2B adapter 实现固定 status 和 staged/unstaged diff；fake Runtime 明确不提供能力。
- Hono 负责 Better Auth 与 Project 所有权；`ProjectChangesService` 负责活动
  Run/Terminal、Lease 连续性、当前 status 路径复核和错误映射。
- 公共 API：
  - `GET /api/projects/:projectId/changes`
  - `GET /api/projects/:projectId/changes/content?path=...`
- 两条响应均使用 `Cache-Control: private, no-store`；浏览器 Query 缓存 `gcTime=0`。

### Git 执行边界

- 固定 `/workspace`、`/workspace/.git`、`/usr/bin/git`、`/bin/bash`、
  `/usr/bin/env` 和 `/usr/bin/head`。
- 以 `env -i` 运行，关闭 system/global config、pager、optional locks、lazy fetch、
  external diff、textconv、fsmonitor 和 submodule traversal。
- 拒绝 `.git/commondir`、`.git/config.worktree` 和
  `extensions.worktreeConfig`；每次读取前解析固定本地 config，include、`filter.*`、
  external command/textconv、fsmonitor、attributesFile、hooksPath 和 worktree 覆盖
  都会拒绝请求。
- status 使用 porcelain v1 NUL 协议，最多 500 项/128 KiB；staged 和 unstaged diff
  各最多 128 KiB。
- 输出直接经 pipe 截断；不会先把完整 diff 写入 `/tmp` 或收进 Worker 内存。
- path 最多 512 字符/32 层，拒绝绝对路径、反斜线、控制字符、`.`、`..` 和 `.git`；
  diff 只能读取刚从当前 status 再确认的精确路径。被过滤的合法 Git 条目通过
  `unsupportedEntries` 明确标记，不能误报 clean。
- `stagedKind` 与 `unstagedKind` 分开保存，支持 rename + modification 等混合状态；
  binary 只返回 Git 文本提示，不传输文件字节。

### 前端

- Project Inspector 启用 Changes tab，覆盖 loading、无沙箱、busy、非 Git、clean、
  changed、binary、truncated、unsupported paths 和 error。
- 列表展示 staged/unstaged 各自语义；混合状态主标记显示 `R/M` 等组合。
- 详情分成 Staged/Unstaged 两段，使用有界可滚动文本。
- 移除中央 Run 导航中重复且禁用的 Changes 占位。
- `390x844` 下 Project Inspector 改为页头可打开的全高抽屉，支持遮罩、关闭按钮、
  Escape、焦点进入/恢复与 Tab 约束；跨过 `760px` 断点会解除 modal 状态，桌面仍保持
  全高三栏。

## 3. 模板与真实端到端验收


构建探针通过 Node `24.16.0`、Pi `0.82.0`、Goose `1.44.0`、Git `2.39.5` 和

真实产品 E2E 使用受邀账号、Cloudflare Worker、D1、Workflow、E2B 和 Gemini 完成：

1. Pi 在新沙箱中初始化 Git、提交 baseline，并制造普通修改、binary、untracked、
   staged rename + unstaged modification。
2. Changes 列表和 staged/unstaged 详情准确；400,000-byte untracked 文件显示
   `truncated`，随后通过 Terminal 清理。
3. Terminal 活动时 Changes 显示 busy；关闭后恢复。
4. 恶意 `filter.*` 配置使 Changes 返回受控错误，标记文件未生成；清理配置后恢复。
5. 临时移走 `.git` 时显示非 repository，恢复后重新读取。
6. 列表/详情响应头均为 `private, no-store`，响应体未出现 Provider、E2B、内部端口、
   `provider_ref` 或 Key 痕迹。
7. 空闲回收后又执行一个最小真实 Pi Run；20 秒成功，D1 记录 28,810 tokens 和
   11 次模型请求，桌面与移动抽屉都读取到真实修改。
8. 最终手动停止测试沙箱；D1 Lease 为 `stopped`，Provider 引用清空，
   `terminal_sessions=0`、`preview_sessions=0`。
9. 审计加固后又用真实 Pi 写入 `.git/config.worktree` 恶意 textconv；Changes 返回
   通用受控错误，Files 确认标记文件未生成。随后清理额外 config scope。
10. 创建 Linux 合法的反斜线文件名后，Changes 显示“Some changes are hidden”且不显示
    clean；移动抽屉跨 `390 -> 1230 -> 390` 断点后不残留 `aria-modal` 或 dialog 状态。
    最终两次 Run 均为 `succeeded`，测试沙箱再次停止且临时 Terminal/Preview 行为 0。

## 5. 基础设施影响

本纵切新增：

- 一项窄 Runtime capability；
- 一项 application service；
- 两条同源 GET API；
- 一个 React Project Inspector view；
- 一个显式包含 Git/Bash/coreutils 的新 E2B immutable build。

没有新增 D1 表、迁移、环境变量、Secret、Cloudflare 资源、R2、Workflow 类型、
Durable Object、第二个 Worker 或外部服务。Changes 不创建沙箱，也不延长 Lease。

## 6. 剩余边界

- status、Lease 和 diff 读取不是事务；这是个人项目下的尽力一致当前视图。
- Changes 不保存历史、不比较 Run 前后、不支持 branch/commit/revision 浏览或写操作。
- repository 自身仍是低信任输入；当前通过固定命令、清空环境、配置拒绝和输出上限
  缩小执行面，但不把它宣传成通用不可信 Git hosting 隔离层。
- import boundary 和 GitHub Actions 基础门禁已在本阶段收尾时补齐；下一阶段优先补
  自动浏览器 smoke 和维护者/每用户成本护栏，再决定 Goose 是否满足公开产品门槛。
